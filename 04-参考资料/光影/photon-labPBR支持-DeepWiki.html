Purpose and Scope

This document explains how Photon Shaders supports the labPBR resource pack format for physically-based rendering materials. labPBR extends Minecraft's texture system to include normal maps and specular maps that encode material properties like roughness, metallic values, subsurface scattering, and emission. For information about hardcoded material properties that serve as defaults when labPBR textures are not present, see Material Categories. For details on how these material properties are used during lighting calculations, see Direct Lighting and Specular.

Sources: README.md48 shaders/include/surface/material.glsl1-22

Texture Format Overview

Photon supports two texture formats controlled by the TEXTURE_FORMAT preprocessor constant:

  • TEXTURE_FORMAT_LAB: Full labPBR specification with support for dielectrics, hardcoded metals, and albedo metals
  • TEXTURE_FORMAT_OLD: Legacy format with simple roughness/metallic/emission encoding

The labPBR format uses specialized texture maps to define material properties beyond albedo:

  • Normal maps: Tangent-space surface detail stored in textures with the _n suffix
  • Specular maps: Material properties encoded in RGBA channels of textures with the _s suffix

Sources: shaders/include/surface/material.glsl38-115

Specular Map Channel Encoding

The labPBR specular map uses all four RGBA channels to encode multiple material properties in a single texture:

ChannelPropertyEncoding Details
RSmoothnessLinear value (0-1), converted to roughness via roughness = (1 - smoothness)²
GMaterial Type< 229.5/255: Dielectric with F0 from G value
229.5-237.5/255: Hardcoded metal ID (230-237)
≥ 237.5/255: Albedo-based metal
BSSS/Porosity< 64.5/255: Porosity (0-64/255 range)
≥ 64.5/255: Subsurface scattering (64-255/255 range)
AEmissionMultiplier for emissive lighting (0-1), where 1.0 = no emission

The alpha channel's special treatment (1.0 = no emission) prevents unintended emission on fully opaque materials.

Hardcoded Metal F0/F82 Values

When the specular map's green channel falls in the range 230-237/255, it encodes one of eight hardcoded metal types. These metals use scientifically accurate Fresnel reflectance values contributed by Jessie LC:

IDMaterialF0 RGBF82 RGB
0Iron(0.78, 0.77, 0.74)(0.74, 0.76, 0.76)
1Gold(1.00, 0.90, 0.61)(1.00, 0.93, 0.73)
2Aluminum(1.00, 0.98, 1.00)(0.96, 0.97, 0.98)
3Chrome(0.77, 0.80, 0.79)(0.74, 0.79, 0.78)
4Copper(1.00, 0.89, 0.73)(1.00, 0.90, 0.80)
5Lead(0.79, 0.87, 0.85)(0.83, 0.80, 0.83)
6Platinum(0.92, 0.90, 0.83)(0.89, 0.87, 0.81)
7Silver(1.00, 1.00, 0.91)(1.00, 1.00, 0.95)

F0 represents reflectance at normal incidence (0° viewing angle), while F82 represents reflectance at 82° grazing angles. This dual-value system enables physically accurate Fresnel effects where metals become more reflective at grazing angles.

Integration with Material System

The material_from function creates materials by first establishing defaults, applying hardcoded properties for specific material masks, and then allowing labPBR textures to override these values. This layered approach ensures materials always have valid properties even when resource packs are incomplete.

SSR Multiplier Calculation

The screen-space reflection multiplier is automatically calculated based on material properties to optimize performance by skipping SSR on surfaces where reflections would be imperceptible:

This calculation (based on Kneemund's method) produces a binary result (0 or 1) that disables SSR for:

  • Low F0 materials: Materials with weak reflectance (F0 < 0.01)
  • High roughness materials: Materials where roughness * SSR_ROUGHNESS_THRESHOLD reduces effective F0 below threshold

The threshold prevents wasted computation on barely-visible reflections while allowing strong reflections to use SSR regardless of roughness.

Legacy Format Support

The TEXTURE_FORMAT_OLD format provides simplified material encoding for compatibility with older resource packs:

ChannelPropertyEncoding
RSmoothnessConverted to roughness: (1 - R)²
GMetallicBinary threshold: G > 0.5 → metal, else dielectric
BEmissionDirect emissive multiplier applied to albedo
AUnusedNot used in legacy format

In this format, metallic materials use albedo as F0 (albedo metal), while dielectrics retain the default F0 of 0.02. No SSS or porosity encoding is supported.

Sources: shaders/include/surface/material.glsl101-114

Emission Handling

Emission from labPBR specular maps is combined with hardcoded emission values using a maximum operation:

This approach allows both systems to coexist:

  • Hardcoded emission: Applied first based on material mask during material_from
  • labPBR emission: Applied during decode_specular_map and takes precedence if stronger
  • No emission flag: Alpha = 1.0 explicitly disables labPBR emission via the multiplication guard

The result is that resource pack creators can override hardcoded emission, but hardcoded emission serves as a fallback for materials without specular maps.

Feature Toggles

Material property application can be controlled via preprocessor flags defined in configuration:

Preprocessor FlagControls
HARDCODED_SPECULAREnables hardcoded roughness/F0 for specific material masks
HARDCODED_SSSEnables hardcoded subsurface scattering for foliage
HARDCODED_EMISSIONEnables hardcoded emissive properties for light sources

When these flags are disabled, materials rely entirely on:

  1. labPBR resource pack data (if present)
  2. Minimal defaults (F0=0.02, roughness=1.0, no SSS/emission)

This allows users to choose between:

  • Hardcoded approach: Artistic control with good defaults even without resource packs
  • Pure PBR approach: Rely solely on physically accurate labPBR textures

The flags are checked via #ifdef directives throughout the hardcoded material assignment code in material_from.

Sources: shaders/include/surface/material.glsl168-174 shaders/include/surface/material.glsl180-214 shaders/include/surface/material.glsl317-331

Rendering Pipeline Integration

The material properties decoded from labPBR textures flow through the deferred rendering pipeline:

  1. Geometry stage: material_from creates materials with labPBR overrides
  2. G-Buffer packing: Material properties are encoded into colortex1 and colortex2
  3. Deferred shading: Properties are decoded in d4_deferred_shading for lighting calculations

The ssr_multiplier specifically controls whether screen-space reflections are computed for each fragment, allowing the renderer to skip expensive SSR raymarching on materials where reflections would be imperceptible.
